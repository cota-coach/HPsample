# デイサービス和乃家 営業提案用TOPページ

## これは何ですか？

営業提案で見せるための**TOPページの試作品**です。Webサイトの見た目とスマートフォン対応までは作成済みですが、インターネット上への公開、本番フォーム、WordPress化はまだ行っていません。

## いちばん簡単なプレビュー方法（非エンジニア向け）

> **先に確認してください：** ファイルがGitHubへ反映・マージ済みの場合に使える手順です。リポジトリの通常画面で `index.html` などのファイルが見えていれば準備完了です。

1. GitHubでファイルを反映したリポジトリを開きます。
2. 緑色の **Code** ボタンを押します。
3. **Download ZIP** を押します。
4. ダウンロードしたZIPファイルを展開します。
5. 展開したフォルダにある `index.html` をダブルクリックします。
6. Chrome、Edge、Safariなどが開き、TOPページを確認できます。

この方法では外部公開されません。自分のパソコン内だけで安全に確認できます。Google Fontsの表示にはインターネット接続が必要ですが、接続できない場合も代替フォントで内容を確認できます。

## PRをマージした後にすること

### まず自分のパソコンだけで確認する（推奨）

PRをマージ済みなら、GitHubで対象リポジトリの通常画面へ戻り、ブランチ表示が `main`（またはPRの取り込み先ブランチ）になっていることを確認します。その後、上記の **Code → Download ZIP** からダウンロードし、`index.html`をダブルクリックしてください。

GitHub上で`index.html`のファイル名をクリックしただけでは、Webサイトの見た目にはなりません。GitHubではHTMLのコードが表示されるのが正常です。

### URLで見られるようにする（GitHub Pages）

営業先へURLを送る前に、まずローカルプレビューで内容を確認してください。問題がなければ、GitHubリポジトリで次の操作を行います。

1. リポジトリ上部の **Settings** を開く。
2. 左メニューの **Pages** を開く。
3. **Build and deployment** のSourceで **Deploy from a branch** を選ぶ。
4. BranchでPRをマージしたブランチ（通常は `main`）と **/ (root)** を選ぶ。
5. **Save** を押す。
6. 数分後に同じPages画面を再読み込みし、表示されたURLを開く。

#### 今回そのまま選ぶ項目

`cota-coach/HPsample`では、次の組み合わせを選びます。

| GitHubの項目 | 選ぶ内容 |
|---|---|
| Source | `Deploy from a branch` |
| Branch | 3ページをマージしたブランチ。通常は `main` |
| Folder | `/ (root)` |

設定後は、リポジトリ上部の **Actions** を開き、Pagesの処理に緑色のチェックが付くまで待ちます。その後、**Settings → Pages**へ戻り、**Visit site**を押してください。公開URLは通常 `https://cota-coach.github.io/HPsample/` という形式です。画面に表示されたURLを正として使用してください。

#### 更新したのに表示が変わらない場合

1. 新しいPRが本当に`main`へマージ済みか確認する。
2. **Actions**で最新のPages処理が緑色のチェックになっているか確認する。
3. 公開URLを開き、Windowsは `Ctrl + F5`、Macは `Command + Shift + R` で再読み込みする。
4. まだ変わらなければ、数分待ってからもう一度開く。

#### 404が表示された場合

- **Settings → Pages**でBranchが`main`、Folderが`/ (root)`になっているか確認する。
- `main`の一番上の階層に`index.html`があるか確認する。
- **Actions**に赤い印がある場合は、その処理を開いてエラー内容を確認する。
- リポジトリ名を変更した場合は、以前のURLではなくPages画面に表示された新しいURLを使う。

この操作はWebサイトをインターネット上へ公開する操作です。営業資料として限定的に見せたい場合は、公開範囲やリポジトリの設定を確認してから行ってください。GitHubの契約・リポジトリ設定によってPagesを利用できない場合があります。

### プレビューで確認する場所

- 最初の画面に「浜田市・認知症対応型通所介護」と表示されるか
- 電話番号が `0855-25-5343` になっているか
- ページを下へスクロールできるか
- スマートフォン幅でメニューが開くか
- 画面下部に電話・お問い合わせボタンが表示されるか
- ニュースや問い合わせ先に「サンプル」「プロトタイプ」の注記があるか

## スマートフォン表示の確認方法

Chromeで `index.html` を開いた状態で、次の手順を行います。

1. ページ上で右クリックし、**検証**を選びます。
2. 開いたパネル左上のスマートフォン／タブレット型のアイコンを押します。
3. 上部の端末一覧から `iPhone` などを選びます。
4. ページを再読み込みして、メニューや画面下部の電話ボタンを確認します。

## 開発者向けの確認方法

ターミナルでこのフォルダへ移動し、以下を実行します。

```bash
python3 -m http.server 4173
```

その後、ブラウザで `http://localhost:4173` を開きます。終了するときはターミナルで `Ctrl + C` を押します。

## GitHubのPRについて

PR（Pull Request）は、新しいフォルダを作る機能ではありません。**変更したファイル一式を、元のブランチへ取り込む前に確認・相談する画面**です。

- この試作品のファイルは、現在ローカルの作業ブランチ内にあります。GitHubで確認するには、そのブランチをGitHubへPushする必要があります。
- PRを作ると、追加・変更されたファイルをGitHub上で一覧確認できます。
- PRを作っただけでは、一般公開用のWebサイトにはなりません。
- 内容を確認して **Merge** すると、変更が元のブランチへ取り込まれます。
- 公開には、別途GitHub Pagesやレンタルサーバーなどの設定が必要です。

### Codex画面の3つの表示の意味

- **ブランチを更新**：Codexの今回の変更を作業ブランチへ反映・更新する操作です。これだけでは通常の`main`画面にはまだ入りません。
- **PRを作成**：作業ブランチから`main`へ変更を取り込むための確認画面をGitHub上に作ります。この時点でも`main`にはまだ入りません。
- **PRを表示**：作成済みのPRをGitHubで開くだけです。ファイルを取り込む操作ではありません。

GitHubの通常の`main`ブランチを更新する最後の操作が**Merge（マージ）**です。PRの **Files changed** で内容を確認し、問題がなければ **Merge pull request → Confirm merge** を押します。これで初めて変更が`main`へ入ります。

基本の順番は次のとおりです。

1. Codexで **ブランチを更新**
2. Codexで **PRを作成**
3. **PRを表示**してGitHubを開く
4. GitHubの **Files changed** で変更ファイルを確認
5. GitHubの **Merge pull request** を押す
6. **Confirm merge** を押す
7. リポジトリ通常画面の`main`でファイルを確認

すでに同じPRをマージした後にCodexが新しい変更を作った場合、その変更には新しいPRと新しいマージが必要です。過去のPRを一度マージしただけでは、その後の変更は自動では入りません。

## GitHubへ反映するには

このプロジェクトでは、ファイル作成とGitのコミットまでは完了しています。対象リポジトリ `cota-coach/HPsample` を接続先として設定しましたが、この実行環境からGitHubへの通信がHTTP 403で拒否されたため、Pushは完了していません。そのため、GitHub上にはまだ表示されません。

### チャット開始時にリポジトリを選ぶこととの違い

チャット開始時に `cota-coach/HPsample` を選ぶ操作は、Codexへ「このリポジトリを作業対象として読み込む」と伝える操作です。実際にCodexは、そこから用意された作業用コピー `/workspace/HPsample` 内のファイルを編集しています。

ただし、**作業対象を選ぶこと**と、**編集結果をGitHubへPushすること**は別の操作です。作業環境によっては、安全のためGitHubの接続先、書き込み認証、外部通信の権限が作業用コピーに引き継がれません。今回は接続先を設定してPushを試みましたが、実行環境の通信制限（HTTP 403）により、Codexが行ったコミットは作業用コピー内にのみ保存されています。

つまり、今回の状態は次のとおりです。

1. `cota-coach/HPsample`を元にした作業用コピーを編集：完了
2. 作業用コピー内でGitコミット：完了
3. GitHubの`cota-coach/HPsample`へPush：未完了（実行環境からの通信がHTTP 403で拒否されたため）

リポジトリ選択だけでPushまで自動実行されるとは限りません。GitHubに反映されたかどうかは、`git remote -v`、`git push`の結果、GitHub上のブランチ表示の3点で確認します。

GitHubへ反映するには、リポジトリのURLと書き込み権限を設定した環境で、次の操作が必要です。

### 非エンジニアの方：`bash`や`git push`は入力しなくて大丈夫です

説明に表示される `bash` は、命令文ではなく「枠内がターミナル用のコマンドである」と示すラベルです。非エンジニアの方がGitHubの検索欄などへ入力する文章ではありません。

今回、利用者側で最初に確認することは1つだけです。**Codex画面の変更一覧または成果物一覧にある「Create PR」「Pull requestを作成」「GitHubへ反映」などのボタンを押せるか確認してください。** ボタンがある場合は、次の順番で操作します。

1. Codex画面で今回のタスクを開く。
2. `index.html`など5ファイルが変更一覧にあることを確認する。
3. **Create PR**（または同じ意味のボタン）を押す。
4. 表示されたタイトルと説明を確認し、作成を確定する。
5. GitHubで開かれたPRの **Files changed** を押し、5ファイルを確認する。

ボタンが表示されない、または押した後にエラーになる場合は、利用者がコマンドを入力して解決する問題ではありません。CodexとGitHubの連携・書き込み権限を設定し直す必要があります。エラー画面をそのまま共有してください。

### Git操作に慣れている方向け（通常は不要）

```bash
git remote add origin <GitHubリポジトリのURL>
git push -u origin work
```

`origin`がすでに登録されている場合、1行目は不要です。Push後、GitHub上で`work`ブランチからPRを作成します。

### GitHub画面から手動でアップロードする場合

コマンド操作をしない場合は、GitHubの対象リポジトリで **Add file → Upload files** を選び、次の5ファイルをアップロードできます。

- `index.html`
- `styles.css`
- `script.js`
- `README.md`
- `ASSET_REQUESTS.md`

ただし、この方法はGitの作業履歴を引き継がないため、リポジトリURLを開発環境へ設定してPushする方法を推奨します。

## ファイルの役割

- `index.html`：ページに載せる文章とセクション構成
- `about.html`：「和乃家について」の下層ページ
- `day.html`：「和乃家での一日」の下層ページ
- `guide.html`：「ご利用・ご相談」の下層ページ

- `ASSET_REQUESTS.md`：正式制作時に用意・差し替えたい写真の一覧
